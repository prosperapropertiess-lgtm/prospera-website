# 07 — Marketing Asset Preparation

## PURPOSE
Produce marketing assets that actually convert views into inquiries, instead of a phone-photo listing that gets scrolled past. Serves: **Vacancy→Tenant**.

## WHEN THIS SOP STARTS
After `06_RENT_READY.md` confirms no open BLOCKER items.

## RESPONSIBLE PERSON
Leasing Lead (photography may be outsourced; copy and review stay in-house).

## ESTIMATED TIME
1–2 hours photo/video shoot + 30–45 min listing copy.

## REQUIRED INPUTS
- Rent-ready property (no BLOCKER items)
- Approved rent recommendation (`04_RENT_PRICING.md`)
- Discovery Call "talking points" (neighbourhood highlights, walk score) if already pulled

---

## PHOTO ORDER SOP

- [ ] Shoot during daylight hours, all lights on regardless — **[CHECKLIST]**
- [ ] Hero shot: the single best room or exterior angle, shot first and reviewed before continuing — **[HUMAN JUDGMENT]**
- [ ] Every room photographed: living areas, kitchen, every bedroom, every bathroom, in-suite laundry if present, parking/exterior — **[CHECKLIST]**
- [ ] Wide-angle where possible, straight lines (not tilted), decluttered before shooting — **[CHECKLIST]**
- [ ] Minimum 10 photos for a standard unit; more for larger/unique properties — **[CHECKLIST]**
- [ ] Floor plan pulled or sketched if available — **[CHECKLIST]**, **[AUTOMATABLE]** if a floor plan tool is in use
- [ ] Virtual staging only if the unit is vacant and shows empty/awkward — **[HUMAN JUDGMENT]**, flag to owner if cost applies — **[OWNER DECISION]**

## LISTING WRITING SOP

Every listing must clearly answer, in order: **WHAT IT IS → PRICE → BEST BENEFITS → WHAT'S INCLUDED → MAJOR FEATURES → AVAILABILITY → LOCATION → CALL TO ACTION.**

- [ ] Pull neighbourhood talking points from the Discovery Call tool if available — **[AUTOMATABLE]** (existing `/api/admin/neighbourhood` engine)
- [ ] Write listing copy following COPYWRITING.md rules — **[AI ASSISTABLE]** (draft), **[HUMAN JUDGMENT]** (approve)
  Hard rule carried over from COPYWRITING.md: never describe the ideal tenant (Ontario Human Rights Code), never guarantee outcomes, no hype words. **[LEGAL REVIEW NEEDED]** applies to any listing language describing who should live there — avoid entirely rather than testing the line.
  Avoid generic filler like "Beautiful property in a great location" — every line should be specific to this property.
- [ ] Feature selection — pick the 3–4 features that actually differentiate this property from active competition (pulled in `04_RENT_PRICING.md` Step 7) — **[HUMAN JUDGMENT]**
- [ ] Proofread and fact-check against the property record (rent, bedrooms, bathrooms, availability date all match exactly) — **[CHECKLIST]**

## COMMON MISTAKES
- Publishing photos before a QC pass — a tilted, dark, or cluttered hero photo is the single biggest silent killer of inquiry volume (see `14_FUNNEL_DIAGNOSTICS.md` — LOW VIEWS/INQUIRIES diagnosis starts here).
- Copy-pasting generic boilerplate across multiple listings — each one needs its own specific benefits.
- Listing a rent or availability date that doesn't match what was actually authorized in onboarding.

## ESCALATION CONDITIONS
- Owner wants virtual staging or professional photography Prospera doesn't have budget authority for → confirm cost split before booking, this is an **[OWNER DECISION]**.

## QUALITY CONTROL
- No listing goes live without: hero photo review, full room coverage, and a proofread copy pass against the property record.

## OUTPUT / DELIVERABLE
A complete photo set, listing copy following the 8-part structure, and (if applicable) a floor plan — ready to load into `08_LISTING_LAUNCH.md`.
