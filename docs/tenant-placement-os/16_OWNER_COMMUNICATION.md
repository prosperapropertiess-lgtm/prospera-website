# 16 — Owner Communication System

## PURPOSE
An owner should never have to chase Prospera for an update. This is the single most trust-building system in the whole operation. Serves: **Owner Communication** (directly — this file exists entirely for this pillar).

## WHEN THIS SOP STARTS
Launch day, and continues on a fixed cadence plus event-triggered updates until lease signed.

## RESPONSIBLE PERSON
Leasing Lead.

## ESTIMATED TIME
10–15 minutes per update.

## REQUIRED INPUTS
- Current funnel scoreboard
- Any showing feedback since the last update
- Any pending decision the owner needs to make

---

## STANDARD UPDATE STRUCTURE
Every update follows this order, every time: **NUMBERS → FEEDBACK → ACTIONS → ASSESSMENT → RECOMMENDATION → NEXT UPDATE DATE.** Concise, calm, professional. Show evidence, never emotion — "we're trying extremely hard" is banned language; a specific number or action replaces it.

## OWNER COMMUNICATION CALENDAR

| Update | Trigger | Timing |
|---|---|---|
| Launch Update | Listing goes live | Day 0, same day |
| Day 7 Update | Scheduled | Day 7 |
| Day 14 Update | Scheduled | Day 14 |
| Price Recommendation | Diagnosed by funnel data | As needed |
| Showing Feedback Update | A showing produces a notable objection/pattern | Within 24h of the showing |
| Strong Applicant Update | A qualified application arrives | Within 24h |
| Application Issue Update | Verification stalls or a red flag appears | Same day |
| Owner Decision Request | A decision is needed from the owner | As needed, with a clear deadline |
| Lease Signed Update | Lease executed | Same day |
| Difficult Market Update | Funnel diagnostics show a structural demand problem | As identified |
| No Qualified Demand Update | Multiple showings, zero qualified applications | As identified |
| 30-Day Vacancy Review | Day 30 checkpoint | Day 30 |

  If the Lease Signed Update has already gone out, skip any remaining Day 7/14/30 scheduled updates — they'd land after the fact and read as out of touch. Triggered updates (Application Issue, Owner Decision Request, etc.) still apply right up until lease signature.
- [ ] Identify which update applies (scheduled or triggered) — **[CHECKLIST]**
- [ ] Pull current numbers from the funnel scoreboard — **[AUTOMATABLE]** / **[CHECKLIST]**
- [ ] Draft using the NUMBERS → FEEDBACK → ACTIONS → ASSESSMENT → RECOMMENDATION → NEXT UPDATE DATE structure — **[AI ASSISTABLE]** draft, **[HUMAN JUDGMENT]** review
- [ ] Send — **[HUMAN JUDGMENT]**
- [ ] Log that the update was sent, with date — **[CHECKLIST]**
  DEFINITION OF DONE: an owner should be able to ask "when did I last hear from you" and the record answers it instantly

## WHEN PROSPERA GETS SOMETHING WRONG
Applies to: rent estimate too high, listing contained an error, an update was late, a follow-up was missed, a showing problem occurred, applicant communication was delayed. Pattern: **OWN IT → CORRECT IT → EXPLAIN NEXT ACTION → PREVENT RECURRENCE.** No groveling, no hiding. See the exact scripts in `25_SCRIPT_LIBRARY.md` and the fuller procedure in `24_EXCEPTION_PLAYBOOK.md`.

## COMMON MISTAKES
- Only communicating when there's good news — silence during a slow stretch is exactly when trust erodes fastest.
- Burying the recommendation at the end of a long narrative instead of using the fixed structure.
- Writing emotional reassurance instead of showing the actual numbers and actions.

## ESCALATION CONDITIONS
- An owner update is more than 48 hours late against the calendar above → treat as a process failure, apply the OWN IT → CORRECT IT pattern to the owner directly.

## QUALITY CONTROL
- 100% of scheduled updates sent on time, logged.
- Zero owners who had to initiate contact asking "any updates?"

## OUTPUT / DELIVERABLE
A logged communication history per owner showing every update sent, on the structure above, on schedule.
