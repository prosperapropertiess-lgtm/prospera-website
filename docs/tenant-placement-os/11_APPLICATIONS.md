# 11 — Application Experience

## PURPOSE
Get applicants started with almost no friction, then progressively collect what's actually needed — instead of demanding every document up front and losing good applicants to a clunky form. Serves: **Vacancy→Tenant**, **Money** (the $99 application fee is disclosed at the right time, not sprung on anyone).

## WHEN THIS SOP STARTS
A lead moves to APPLIED after a showing marked INTERESTED (`10_SHOWINGS.md`).

## RESPONSIBLE PERSON
Leasing Lead.

## ESTIMATED TIME
2 minutes for the applicant at Quick Apply; 15–20 minutes of Prospera review across the full funnel.

## REQUIRED INPUTS
- Showing outcome = INTERESTED
- Prequalification answers already captured pre-showing (budget, dealbreakers, verification consent, $99 fee disclosure already given)

---

## THE 5-STEP APPLICATION FUNNEL

- [ ] **Step 1 — Quick Apply (~2 minutes).** — **[AUTOMATABLE]**
  Name, contact info, move-in date, confirm interest, confirm awareness of the $99 application fee (already disclosed pre-showing — this is a re-confirmation, not the first mention). No documents required yet.

- [ ] **Step 2 — Preliminary Review.** — **[HUMAN JUDGMENT]**, **[AI ASSISTABLE]** for a first pass
  Sanity check: does the application match what was discussed (household size vs. property, stated income range plausible for the rent)? This is a plausibility check, not a decision — never reject at this stage based on judgment about the applicant as a person, only on stated facts not fitting the property. **[LEGAL REVIEW NEEDED]** — ensure this step never functions as an informal, undocumented screening step that bypasses `12_SCREENING.md`.

- [ ] **Step 3 — Document / Verification Request.** — **[AUTOMATABLE]** for the request, **[CHECKLIST]** for tracking
  Request ID, proof of income/employment, rental history/references — only now, not at viewing or Quick Apply. SCRIPT: Documents Missing Script.

- [ ] **Step 4 — Full Screening.** — see `12_SCREENING.md`

- [ ] **Step 5 — Owner Review / Decision.** — **[OWNER DECISION]**
  Present the Owner Applicant Summary Template (`27_TEMPLATE_LIBRARY.md`), owner makes the final call.

## STATUS-SPECIFIC SCRIPTS
(all in `25_SCRIPT_LIBRARY.md`)
- Application Started But Not Finished — nudge at 24h and 72h
- Documents Missing — specific, itemized ask, not "please send your documents"
- Reference Outstanding — polite chase to the reference, not the applicant, when it's the reference who's slow
- Employment Verification — direct, professional ask to employer/HR
- Application Withdrawn — clean, no-pressure acknowledgment
- Application Status Update — sent proactively, applicant should never have to ask

## COMMON MISTAKES
- Front-loading every document requirement into Quick Apply — this is the #1 cause of application abandonment (see `14_FUNNEL_DIAGNOSTICS.md`: SHOWINGS + LOW APPLICATIONS vs. APPLICATION ABANDONMENT are different problems with different fixes).
- Letting an application sit in VERIFYING with no status update to the applicant — silence reads as rejection and good applicants walk.
- Confirming the $99 fee disclosure only once, at Quick Apply, without it having already been raised during prequalification — the flow depends on this being said twice: once pre-showing, once at application, never as a surprise.

## ESCALATION CONDITIONS
- Applicant disputes the $99 fee or claims it wasn't disclosed → pull the prequalification record showing the disclosure checkbox/consent, resolve directly; if the record shows it genuinely wasn't disclosed, that's a process failure — own it per `18_MOVE_IN_HANDOFF.md`'s "when we get something wrong" pattern (see `24_EXCEPTION_PLAYBOOK.md`).

## QUALITY CONTROL
- No document is requested before Step 3.
- Every applicant gets a status update at least every 3 business days while active.

## OUTPUT / DELIVERABLE
A completed application funnel from Quick Apply through Owner Review, with every stage timestamped.
