# 23 — Employee Training System

## PURPOSE
Turn this entire operating system into a repeatable training path — the direct answer to "I should be able to give this whole leasing engine to a newbie... and get the same result every time." Serves: all 5 pillars, by making quality independent of who's running leasing.

## WHEN THIS SOP STARTS
A new person is being trained to run any part of tenant placement.

## RESPONSIBLE PERSON
Ebin (Day 1), then the trainee under supervision (Week 1+).

## ESTIMATED TIME
Day 1: half day. Week 1: full week of shadowed + supervised work. Certification: ongoing until demonstrated.

## REQUIRED INPUTS
- This entire operating system (files 00–27)
- Access to the live tools (Discovery Call, admin console, booking flow)

---

## DAY 1 TRAINING
- [ ] Walk through `00_MASTER_TENANT_PLACEMENT_WORKFLOW.md` end to end — the whole pipeline, in order — **[HUMAN JUDGMENT]**
- [ ] Explain the 5 pillars and why every SOP maps back to one — **[HUMAN JUDGMENT]**
- [ ] Explain controllables vs. uncontrollables (`03_OWNER_EXPECTATIONS.md`) — this is the mindset the whole system is built on
- [ ] Walk through the live tools: Discovery Call tool, admin console, booking/prequalification flow
- [ ] Read `12_SCREENING.md`'s Human Rights Code section in full — this is non-negotiable before touching any real applicant

## WEEK 1 TRAINING
- [ ] Shadow a full Discovery Call — **[HUMAN JUDGMENT]**
- [ ] Shadow a full showing — **[HUMAN JUDGMENT]**
- [ ] Shadow one full owner update cycle — **[HUMAN JUDGMENT]**
- [ ] Run the Daily Leasing Routine under supervision, 5 consecutive business days — **[HUMAN JUDGMENT]**

## SHADOWING CHECKLIST
- [ ] Observed a Discovery Call and could explain the AI verdict reasoning afterward
- [ ] Observed a showing and correctly logged the outcome + objection reason independently
- [ ] Observed screening and could explain, unprompted, why a specific criterion is or isn't lawful to use
- [ ] Observed an owner update and could identify all 6 structure elements (Numbers/Feedback/Actions/Assessment/Recommendation/Next Date) in it

## PRACTICE SCENARIOS
Run the trainee through the 7 reality-test scenarios from `00_MASTER_TENANT_PLACEMENT_WORKFLOW.md` (Scenarios A–G) as case studies — have them propose the diagnosis and next action for each, then compare against the documented answer.

## CERTIFICATION CHECKLIST
Before operating independently, demonstrate competence in:
- [ ] Pricing — can run the 8-step comparable process and produce 3 price positions unaided
- [ ] Listing creation — can produce a compliant, complete listing (photo order + copy structure) unaided
- [ ] Lead response — hits response-time targets for a full week unsupervised
- [ ] Showings — runs a showing and logs outcome correctly unsupervised
- [ ] Applications — correctly sequences the 5-step funnel without front-loading documents
- [ ] Owner communication — drafts a compliant update using the fixed structure unaided
- [ ] Funnel diagnosis — correctly diagnoses 2 out of 2 practice scenarios using the diagnosis table
- [ ] Escalation — can state, from memory, what happens at each of the 6 vacancy escalation checkpoints

## COMMON MISTAKES
- Certifying someone on process knowledge alone without observing them handle a real (or realistic practice) screening/Human-Rights-Code scenario.
- Skipping shadowing steps because the trainee "seems to get it" — the system's whole premise is that judgment isn't enough; the checklist has to actually be followed.

## ESCALATION CONDITIONS
- A trainee fails certification on the screening/Human Rights Code component → do not certify, re-train and re-test specifically on that component before any other retest.

## QUALITY CONTROL
- No one runs tenant placement independently without completing the full certification checklist.

## OUTPUT / DELIVERABLE
A certified employee who can run the entire leasing engine to the same standard, unsupervised.
