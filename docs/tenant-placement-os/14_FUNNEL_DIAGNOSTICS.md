# 14 — Funnel Diagnostics

## PURPOSE
Turn raw funnel numbers into a specific diagnosis and a specific fix — never just "it's not renting, let's wait and see." This is the anti-"post and pray" engine. Serves: **Vacancy→Tenant**, **Money**.

## WHEN THIS SOP STARTS
Continuously for every active vacancy; formally reviewed at every checkpoint in `15_VACANCY_ESCALATION.md` and every Daily Leasing Routine.

## RESPONSIBLE PERSON
Leasing Lead.

## ESTIMATED TIME
5–10 minutes per active vacancy per review.

## REQUIRED INPUTS
- Listing views, inquiries, qualified inquiries, showings booked, showings completed, applications, qualified applications, leases — per vacancy

---

## FUNNEL SCOREBOARD

Track for every active vacancy: **LISTING VIEWS → INQUIRIES → QUALIFIED INQUIRIES → SHOWINGS BOOKED → SHOWINGS COMPLETED → APPLICATIONS → QUALIFIED APPLICATIONS → LEASES.** Calculate the conversion rate between every consecutive pair. Template in `27_TEMPLATE_LIBRARY.md`.

## DIAGNOSIS TABLE

| Pattern observed | Diagnosis | What to actually do |
|---|---|---|
| Low views | Exposure/presentation problem | Check channel coverage (`08_LISTING_LAUNCH.md` — is it live everywhere it should be?); check hero photo quality (`07_MARKETING_PREPARATION.md`) |
| High views + low inquiries | Offer/price/positioning problem | Re-run `04_RENT_PRICING.md` Steps 6–7 (active competition); review listing copy's benefit framing |
| Inquiries + low showings booked | Process/expectation problem | Review response time against the target in `09_LEAD_MANAGEMENT.md`; check for booking-flow friction |
| Showings + low applications | Property/price/value problem | Pull the objection-reason data from `10_SHOWINGS.md` — what category dominates (price/condition/layout/etc.)? Address that specific thing, not a generic "make it more appealing" |
| Application abandonment | Friction problem | Check whether documents were requested too early (`11_APPLICATIONS.md` Step 3 discipline) |
| Many unqualified applications | Targeting/qualification problem | Review whether Quick Apply's stated criteria (budget, move date) match what's actually being marketed — misaligned listing copy attracts the wrong applicants |

## FUNNEL REVIEW CHECKLIST

- [ ] Pull current-stage counts for the vacancy — **[AUTOMATABLE]** where tracked in the system, **[CHECKLIST]** otherwise
- [ ] Calculate stage-to-stage conversion — **[AUTOMATABLE]** / **[CHECKLIST]**
- [ ] Identify the weakest conversion point — **[HUMAN JUDGMENT]**
- [ ] Match to the diagnosis table above — **[HUMAN JUDGMENT]**
- [ ] Choose and log one specific corrective action — **[HUMAN JUDGMENT]**
  DEFINITION OF DONE: the action is concrete enough that someone else could execute it without asking what was meant
- [ ] Re-measure after the action has had time to show effect (minimum 3–5 days) — **[CHECKLIST]**
  This is the MEASURE → DIAGNOSE → ACT → MEASURE AGAIN loop — don't skip the re-measure step, it's what separates this from guessing.

## COMMON MISTAKES
- Diagnosing from a single data point instead of the conversion pattern — a slow week isn't automatically a pricing problem.
- Taking action but never re-measuring, so nobody knows if the fix worked.
- Treating "low views" and "high views/low inquiries" as the same problem — they have opposite fixes (exposure vs. offer) and mixing them wastes the correction.

## ESCALATION CONDITIONS
- Same diagnosis repeats after a corrective action has already been tried once → escalate to a full strategy review, don't repeat the same fix a third time (see `15_VACANCY_ESCALATION.md` Day 21 checkpoint).

## QUALITY CONTROL
- Every active vacancy has an up-to-date funnel scoreboard, reviewed at minimum weekly.

## OUTPUT / DELIVERABLE
A funnel scoreboard per active vacancy with the current weakest conversion point identified and one logged corrective action.
